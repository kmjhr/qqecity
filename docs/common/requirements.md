# 《青启e城》需求清单（可执行版）

> 依据：用户原始材料《工行杯9.26.docx》（参赛方案全文）、《青启e城项目系统设计说明书》、《docs/01-技术选型明细.md / 02-项目目录结构.md / 03-MVP开发排期.md / 05-AI协助开发完整计划书.md》。
> 用途：作为 AI 协作开发的需求基线——每个功能点都可用「角色 + 页面 + 操作」描述，可与设计说明书章节一一追溯，P0 范围可在 14 周（Sprint 0—5）内完成演示闭环。

---

## 一、项目范围

**一句话定位**：青启e城是面向青年（在校大学生、应届毕业生、Z世代城市青年）的城市新场景一体化金融智能服务平台（演示系统），覆盖「入城安居、城市轻创业、碎片消费」三大场景，提供保函、小额授信、预算储蓄、反诈守护等普惠金融服务。

**范围边界**：
- 以**可演示闭环**为交付目标（网页端可点通、数据可看、流程可走），全部银行能力以**模拟桩**实现，不接入真实银行系统。
- 部署形态：网页（公网可访问）+ 小程序端（规划第六步，复用同一后端）。

## 二、角色定义

| 角色 | 说明 | 演示系统中的落地 |
| --- | --- | --- |
| 青年用户（租客/借款人/消费者） | 在校大学生、应届毕业生、Z世代城市青年，系统核心用户 | 注册/登录后使用全部业务功能 |
| 房东（保函受益人） | 与租客达成租赁意向的房东，接收保函、发起索赔 | 由演示账号模拟（手机号+验证确认） |
| 商户（受托支付收款方） | 青年创业的物料/摊位/推广服务商 | 预置商户列表，受托支付定向打款目标 |
| 银行运营岗（人工复核） | 保函索赔复核、贷款审核的人工角色 | 管理端简化：规则命中时状态流转至"人工复核"，演示中自动通过并标注 |

| 业务场景 | 对应模块 | 覆盖的功能域 |
| --- | --- | --- |
| 场景一 · 青年入城安居（就业护航） | 模块1 安居金融风控 | 租房履约保函全流程、AI合同复审、违约索赔 |
| 场景二 · 城市轻创业（创业赋能） | 模块2 轻创业智能授信、模块3 创业经营赋能 | 青创e贷A/B授信、受托支付、AI记账 |

| 公共支撑 | 用户与授权、消息中心 | 注册/登录/JWT、站内消息 |

## 五、非功能需求

| 类别 | 需求 | 验收口径 |
| --- | --- | --- |
| 性能 | 页面响应、接口吞吐满足演示级 | 100 并发下登录/列表接口无 5xx，P95 延迟 < 1s（Sprint 8 压测） |
| 安全 | JWT 鉴权、越权防护、密码散列、敏感字段脱敏 | 无 Token/伪造 Token 返回 2001；用户 A 无法访问用户 B 数据；密码 SHA-256 存储（正式化换 BCrypt） |
| 易用 | 演示导航清晰、模拟数据显式标注"模拟" | 主链路 5 分钟内可走通，所有模拟能力在页面有标注 |
| 可维护 | 分层模块化、统一返回、Swagger 文档 | 接口可通过 Swagger 查看，新增模块按四件套模板扩展 |
| 并发 | 演示级并发（多用户同时演示） | 容器部署 + 数据库连接池默认配置即可满足 |

## 六、边界（明确暂不做）

1. 真实征信查询、真实放款、真实保函开立（银行能力全部模拟桩）。
2. 保险代销结算（需保险公司对接）。
3. 防刷单三道防线完整实现（仅预留说明）。
4. RAG 对话引擎、数据中台画像完整建模（二期探索）。
5. Redis 限流（一期不强依赖）。
6. 支付前弹窗提醒（依赖工行自有支付页面，演示不模拟）。
7. 小程序端（第六步规划，本期不做）。
8. 政府/银行真实数据对接。

## 七、演示主链路（验收基线）

> 验收时按此链路逐环节走通，作为 MVP 里程碑（Sprint 5）唯一验收主路径。

```
1. 注册/登录 → 2. 场景一：提交保函申请 → 3. 房东确认 → 4. AI 合同复审通过 →
5. 缴费出函 → 6. 查询保函（状态=已开立）→ 7. 场景二：B 类免费预审（返回额度区间，无征信查询）→
8. 指定商户受托支付模拟（资金定向商户）→ 9. 场景三：设置分类预算 →
10. 模拟交易归类扣减 → 11. 触发分级提醒（50%→20%→超支）→
12. 结余转储蓄 → 13. 安全：输入"征信修复"话术被拦截警示 → 14. 消息中心收到对应提醒
```
