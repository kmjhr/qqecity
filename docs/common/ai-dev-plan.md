# 《青启e城》AI 协助开发完整计划书

> 项目：青启e城 · 青年金融智能服务平台（演示系统）
> 本文档依据《青启e城项目系统设计说明书》及 `docs/01-技术选型明细.md`、`02-项目目录结构.md`、`03-MVP开发排期.md`、`04-开发路线图.html` 整合编写。
> 目标：按「利用 AI 开发系统」的分步流程，从 0 到 1 完成——**需求梳理 → 原型设计 → 数据库设计 → 后端 → 前端网页 → 小程序端 → 测试 → 网页部署 → 小程序上线 → 运维**，最终让其他人可以通过网页和小程序访问使用本系统。
> 使用方式：每一步对照「AI 该做什么 / 我该做什么 / 产出物 / 检查要点」执行；文末附录提供可直接复制发送给 AI 的固定协作指令。

---

## 〇、总体路线与协作模式

| 阶段 | 步骤 | 主要产出 | 参与方 |
| --- | --- | --- | --- |
| 规划 | 1 需求梳理 → 2 原型设计 → 3 数据库设计 | 需求清单、原型稿、ER 与建表 SQL | 你主导，AI 辅助产出 |
| 开发 | 4 后端 → 5 前端网页 → 6 小程序端 | 可运行代码、接口文档 | AI 主力写码，你验收 |
| 交付 | 7 测试 → 8 网页部署 → 9 小程序上线 → 10 运维 | 公网网页 + 微信小程序 | AI 执行，你提供账号/服务器/资质 |

**技术栈基线（已确定，不轻易变更）**：

| 层 | 选型 |
| --- | --- |
| 后端 | Java 17 + Spring Boot 3.2.5 + MyBatis-Plus 3.5.x + MySQL 8 + JWT(jjwt 0.12.x) + springdoc(Swagger) |
| 前端网页 | Vue 3 + Vite 5 + Element Plus + Pinia + Axios |
| 小程序端 | uni-app（Vue3 语法，编译到微信小程序；复用后端 `/api/v1` 接口契约） |
| 部署 | Docker Compose + Nginx + 云服务器 + HTTPS 域名 |

**统一约定**：接口前缀 `/api/v1`；统一返回 `{"code":0,"message":"success","data":...}`；错误码 0/1001/1002/2001/2002/3001/3002/4001/5000；鉴权 `Authorization: Bearer <JWT>`；演示数据一律标注"模拟"。

## 第一步：项目需求梳理

**目标**：把《青启e城》的业务诉求固化为一份可执行的需求清单（范围、角色、场景、功能、边界）。

### AI 该做什么
1. 读取设计说明书与已有 `docs/`，输出「需求清单」：功能需求（按模块拆条）、非功能需求（性能/安全/易用/可维护/并发）、边界（暂不做清单）。
2. 将需求按「用户与授权、安居保函（模块1）、轻创业授信（模块2）、经营赋能（模块3）、碎片消费治理（模块4）、金融安全（模块5）」分组。
3. 为每条需求标注优先级（P0 必做 / P1 演示闭环 / P2 后置），并对齐 Sprint 0—8 排期。
4. 输出「暂不做」清单：真实征信、真实放款/保函开立、保险代销结算、RAG 对话、防刷单复杂规则、Redis 限流、性能压测。

### 我该做什么
1. 提供原始业务素材（工行杯文档 / 设计说明书 / 竞赛要求 / 评分标准）。
2. 确认需求清单：逐条核对是否符合课程/比赛要求，圈定 P0 范围。
3. 拍板边界：明确"哪些银行能力用模拟桩"（预审不查征信、受托支付模拟、保函规则复审）。
4. 确认目标用户与演示主链路：**注册 → 保函 → 预审贷款 → 设预算 → 触发提醒 → 反诈甄别**。

### 产出物
- 《需求清单》文档（含优先级与边界）
- 演示主链路一条（验收基线）

### 检查要点
- [ ] 每个功能点是否可被"某个角色在某个页面点击某按钮"描述？
- [ ] P0 清单是否恰好覆盖三大场景闭环且可在 14 周内完成？
- [ ] 所有"模拟"能力是否被显式标注，未承诺真实金融服务？
- [ ] 需求是否与设计说明书章节一一可追溯？

## 第二步：原型设计

**目标**：确定每个页面的布局、字段、交互与页面流转，作为前后端开发的"图纸"。

### AI 该做什么
1. 根据需求清单输出页面清单：登录页、首页、保函页、贷款页、预算页、记账页（占位）、安全页、消息中心，以及（规划）小程序端同构页面。
2. 为每个页面产出线框描述：页面分区（顶部导航/侧边菜单/内容区）、表单字段、列表字段、按钮与状态流转。
3. 输出页面跳转关系图（路由图）：登录 → 首页 → 各功能页，未登录统一重定向登录页。
4. 若你要求可视化原型，用 HTML 生成可点击的静态原型页（不依赖后端）。

### 我该做什么
1. 确认页面清单与信息架构（哪些页面一期做、哪些占位）。
2. 逐页核对字段：如保函申请表单（姓名/证件号/租房合同号/房东信息/金额/期限）、贷款预审表单（人群类型/创业项目/拟贷金额）。
3. 确认交互规则：预算提醒阈值（50%/20%/超支）、骗局甄别话术规则、消息中心入口。

### 产出物
- 页面清单 + 每页线框描述
- 路由跳转图
- （可选）可点击 HTML 原型

### 检查要点
- [ ] 每页字段是否都能映射到数据库表字段或接口参数？
- [ ] 演示主链路上每个环节都有对应页面与跳转？
- [ ] 占位页面是否明确标注"演示占位"？
- [ ] 原型是否与设计说明书第 5 章模块职责一致？

## 第三步：数据库设计

**目标**：落地 25 张表的结构（字段、类型、主键、索引、外键关系），确保与说明书第 6 章一致。

### AI 该做什么
1. 依据设计说明书第 6 章，输出 25 张表的建表 SQL（`schema.sql`）：表名、全部字段、类型、主键、唯一键、索引、注释。
2. 输出 ER 关系描述（文字）：用户 ↔ 授权、保函申请 → 保函信息 → 理赔、贷款申请 → 额度 → 受托支付、预算 → 交易、风控 → 预警/反诈记录、消息 → 推送等。
3. 生成演示数据（`data.sql`）：演示账号（admin/testuser 等 / 123456，密码 BCrypt 散列）、保函/贷款/预算/消息样例数据。
4. 校验：表数量=25、每张表有主键、与代码实体字段一一对应。

### 我该做什么
1. 提供设计说明书第 6 章（或确认 AI 按其复刻）。
2. 核对关键业务字段口径：金额精度（DECIMAL）、状态枚举值（如保函状态 0待确认/1待缴费/2已开立）、用户人群类型（应届毕业生/青年创业者等）。
3. 确认演示账号与演示数据数量（保证各页面有数据可看）。

### 产出物
- `backend/src/main/resources/db/schema.sql`（25 张表）
- `backend/src/main/resources/db/data.sql`（演示数据）
- ER 图/ER 文字描述

### 检查要点
- [ ] 表数量=25，表名与说明书第 6 章逐一对应？
- [ ] 每张表均有主键，关联表有外键/索引？
- [ ] 金额字段为 DECIMAL 而非 FLOAT？
- [ ] `data.sql` 可重复导入（幂等）？
- [ ] 演示账号密码散列与后端校验算法一致？

## 第四步：后端开发

**目标**：实现全部业务接口（JWT 鉴权 + 7 个模块），通过 Swagger 可查看、可用 curl/前端联调。

### AI 该做什么
1. 搭建/维护 Spring Boot 骨架：`common`（Result/ErrorCode/BizException/GlobalExceptionHandler）、`config`（跨域、MyBatis-Plus）、`security`（JwtUtil/JwtAuthFilter/UserContext，密码校验用 BCryptPasswordEncoder）。
2. 按模块开发四件套（Entity + Mapper + Service + Controller）：
   - `user`：注册、登录、当前用户（/api/v1/auth/register、/login、/me）
   - `guarantee`：保函申请、房东确认、AI 合同复审（规则）、缴费出函、保函查询
   - `loan`：青创e贷 B 类预审（不查征信、额度区间）、A/B 授信、受托支付模拟、额度查询
   - `budget`：分类预算设置、交易归类（MCC 模拟）、分级提醒、结余转储蓄
   - `bookkeeping`：记账/现金流报表占位接口
   - `safety`：反诈内容、骗局甄别规则（征信修复/洗白话术拦截）
   - `message`：消息列表、已读
3. 保证所有接口返回统一结构、错误码符合约定；JWT 过滤器保护业务接口、放行 `/api/v1/auth/**`。
4. 编写/维护 Swagger 注解，输出接口文档。

### 我该做什么
1. 提供运行环境（本机 JDK17 + IDEA 或 Maven；或 Docker）。
2. 验收接口：用 Knife4j 逐个调用，核对入参出参与说明书第 8 章一致。
3. 核对业务规则：保函复审命中风险词转人工、预审 B 类不触发征信、预算提醒阈值正确。
4. 对"银行能力"确认模拟桩行为（额度区间规则、受托支付定向商户）。

### 产出物
- 可运行后端（49+ 个 Java 文件）
- Knife4j 接口文档（本地 `/api/doc.html`）
- 接口自测记录（curl 或 Swagger 截图）

### 检查要点
- [ ] `mvn package` 通过、应用可启动（端口避开占用，如 8082）？
- [ ] 登录成功返回 JWT；携带 Token 可访问受保护接口，无 Token 返回 1002？
- [ ] 所有接口返回 `{code,message,data}`，错误码符合 8.2 约定？
- [ ] 每模块主链路接口可用且业务规则正确？
- [ ] 演示账号能走通"注册→登录→调业务接口"？

## 第五步：前端网页开发

**目标**：实现 Vue3 前端全部页面（登录/首页/保函/贷款/预算/记账/安全/消息），与后端联调通过，`npm run build` 产出可部署静态包。

### AI 该做什么
1. 搭建/维护 Vue3 + Vite5 工程：路由守卫（未登录跳登录）、Pinia 用户态、Axios 封装（baseURL `/api/v1`、Token 注入、统一错误提示、1002 自动登出）。
2. 按原型实现页面：
   - Login：手机号+密码登录、注册入口
   - Home：模块入口卡片、快捷演示
   - Guarantee：保函申请表单、状态流转展示
   - Loan：预审表单、额度区间结果、受托支付模拟
   - Budget：预算设置、交易归类列表、提醒状态
   - Bookkeeping：记账/报表占位页
   - Safety：反诈教学、骗局甄别输入
   - Message：消息列表与已读
3. 开发代理：Vite `/api` → 后端（本机 8080 被占用时用 `VITE_API_TARGET` 指到实际端口）。
4. 生产构建：`npm run build` 输出 `dist/`，配合 `nginx.conf`（静态托管 + `/api` 反向代理）。

### 我该做什么
1. 验收每个页面：能登录、能走通主链路、字段提示合理、空数据有兜底。
2. 核对视觉与文案：统一风格、演示数据标注"模拟"、金额单位、状态文案。
3. 确认交互细节：表单校验、按钮 loading、错误提示不裸奔。

### 产出物
- 完整 Vue3 前端源码
- `dist/` 静态构建产物
- 联调通过截图/录屏

### 检查要点
- [ ] `npm run build` 通过，`dist/` 可被 Nginx 静态托管？
- [ ] 未登录访问业务页被重定向登录页？
- [ ] 登录 → 保函 → 贷款 → 预算 → 安全主链路在页面上完整可走？
- [ ] 后端异常时页面有友好提示而非白屏？
- [ ] 移动端宽度下布局不破（为小程序端作参考）？

## 第六步：小程序端开发

**目标**：基于 uni-app（Vue3 语法）开发微信小程序端，复用后端 `/api/v1` 接口，可被微信开发者工具编译预览。

### AI 该做什么
1. 新建 uni-app（Vue3 + Vite）工程，页面与网页端同构：登录、首页、保函、贷款、预算、记账、安全、消息。
2. 封装小程序端请求层：`baseURL` 指向**公网 HTTPS 域名**，请求携带 JWT；处理登录态与错误码（与网页端逻辑一致）。
3. 按微信小程序规范适配：页面路由、组件引用、`<button open-type>`（如需授权）、滚动加载等。
4. 输出 `manifest.json` 配置（AppID 占位、request 合法域名说明）与构建说明（HBuilderX 或 CLI `npm run build:mp-weixin`）。
5. 提供真机/工具预览的联调清单（域名白名单配置步骤）。

### 我该做什么
1. 注册微信小程序账号（个人或企业主体），获取 **AppID**。
2. 在微信公众平台配置 **request 合法域名**（必须 HTTPS、已备案）。
3. 安装微信开发者工具，导入 uni-app 构建产物进行预览调试。
4. 确认小程序 UI 与网页端信息一致，演示数据标注"模拟"。

### 产出物
- uni-app 小程序源码 + `dist/build/mp-weixin` 构建产物
- 微信开发者工具可打开预览的项目
- 联调记录（含域名白名单配置）

### 检查要点
- [ ] 小程序构建产物可被微信开发者工具正常导入预览？
- [ ] 登录、主链路接口在 HTTPS 域名下可用（无"不在合法域名列表"报错）？
- [ ] Token 持久化与自动登出与网页端一致？
- [ ] 页面在 375pt 宽度下无溢出、无横向滚动？
- [ ] 所有对外文案标注"模拟演示"？

## 第七步：测试

**目标**：功能正确性 + 安全 + 性能达到可对外演示/上线标准。

### AI 该做什么
1. 功能测试：按演示主链路逐环节测试（后端接口 + 前端页面 + 小程序），输出用例表（用例编号/步骤/预期/结果）。
2. 异常测试：错误密码、无 Token、重复注册、超支预算、骗局话术命中、空数据页面。
3. 安全测试：JWT 伪造/过期、越权访问他人数据（userId 越权）、SQL 注入（演示系统至少防注入）、密码存储强度核查。
4. 性能测试：用压测工具（如 JMeter/Apache Bench）对登录、列表接口压测，给出吞吐与延迟结论（演示级 100 并发即可）。
5. 输出《测试报告》：结论、遗留问题、修复建议。

### 我该做什么
1. 提供测试账号与验收标准（演示主链路）。
2. 亲自走一遍主链路（网页端 + 小程序端），记录问题。
3. 对"越权""伪造 Token"类问题重点复核（涉及个人信息，必须修）。
4. 确认遗留问题清单：哪些可上线、哪些必须修。

### 产出物
- 测试用例表 + 测试报告
- 缺陷清单（状态：已修/遗留）

### 检查要点
- [ ] 演示主链路全绿？
- [ ] 越权访问被拦截（用户 A 无法读取用户 B 数据）？
- [ ] 无 Token/伪造 Token 返回 1002？
- [ ] 压测下登录/列表接口无 5xx、无长时间阻塞？
- [ ] 遗留缺陷均有明确处理决定（修/接受/后置）？

## 第八步：网页部署（公网可访问）

**目标**：把系统部署到云服务器，通过域名 + HTTPS 让**其他人**能访问网页版。

### AI 该做什么
1. 给出部署方案：云服务器（建议 2C4G 起步，Ubuntu 22.04/Debian）+ Docker Compose（mysql/backend/frontend 三服务）+ Nginx 反向代理 + HTTPS（Let's Encrypt 或云厂商证书）。
2. 提供服务器初始化脚本：安装 Docker、克隆代码、配置环境变量（数据库密码、JWT 密钥）、`docker compose up -d --build`。
3. 提供 Nginx 配置：`/` → 前端静态资源（8088 或直接 80），`/api` → 后端（8082），WebSocket/长连接按需。
4. 提供 HTTPS 配置步骤与证书自动续期（certbot）。
5. 部署后做公网验证：域名可访问、接口可用、HTTPS 证书有效。

### 我该做什么
1. 购买云服务器（阿里云/腾讯云/华为云）与**域名**，完成 ICP 备案（国内服务器必须，备案通常 1—3 周，提前办理）。
2. 提供服务器 SSH 访问权限给部署流程。
3. 解析域名 A 记录到服务器 IP。
4. 确认部署安全项：数据库密码改强、JWT 密钥改随机、关闭不必要端口。

### 产出物
- 公网可访问网页（如 `https://qingqi.example.com`）
- 部署脚本 + Nginx 配置 + HTTPS 证书
- 部署文档（含回滚方式）

### 检查要点
- [ ] 公网域名 + HTTPS 可访问首页？
- [ ] `/api` 反向代理正常，登录/业务接口可用？
- [ ] 证书无警告，HTTP 自动跳转 HTTPS？
- [ ] 数据库不暴露公网（仅内网/白名单）？
- [ ] 重启服务器后服务能自动恢复（容器 restart 策略）？

## 第九步：小程序上线

**目标**：小程序通过微信审核、正式发布，其他人可在微信中搜索/扫码使用。

### AI 该做什么
