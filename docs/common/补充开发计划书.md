### 1.3 表复用与新增原则

1. **优先复用现有 25 表**，尤其三张预留表：
   - G-6 索赔 → `biz_guarantee_claim`（状态机字段已齐：SUBMITTED→AI_REVIEW→MANUAL_REVIEW→DEFENSE_PERIOD→APPROVED/REJECTED/CLOSED）
   - 征信解读/监测 → `biz_credit_report`（source=SIMULATED）
   - 逾期预判/高频借贷/征信异常/预算超支/现金流预警 → 统一落 `biz_risk_warning`（warning_type 已定义）
2. **确需新增的表**（仅 4 张，走 schema.sql + database-design.md 同步流程，并同步 docker 数据卷初始化说明）：
   - `biz_policy` 政策库（安居/贴息政策，含人群匹配标签）
   - `biz_insurance_product` 保险产品库（履约保证/知识产权，模拟）
   - `biz_finance_product` + `biz_risk_assessment` 理财匹配与风险测评
   - 流水聚合可复用 `biz_transaction` 扩展 `source_channel` 字段，不单独建表
3. 新增表必须：schema.sql 落 DDL → data.sql 落演示数据 → database-design.md 同步 → 重启前 `docker compose down` 重建数据卷或手工 `CREATE TABLE`（与现状核对单口径一致）。

## 三、开发步骤

### 步骤1：保函增强（G-6 索赔闭环 + 电子签约 + AI 预审转人工）

#### ① AI 该做什么

- **G-6 索赔闭环**（对接 `biz_guarantee_claim`，缺口 #9）：
  1. 房东发起索赔：提交索赔金额、原因、证据材料（欠租记录/损坏照片/物品清单/沟通记录，`evidence_files` JSON）；
  2. 状态机：SUBMITTED → AI_REVIEW（AI 初审：证据是否齐全、损坏是否在交接清单中已存在、金额是否超保函额）→ 低风险小案直接 APPROVED；存疑 → DEFENSE_PERIOD（租客收到通知，可提交 `defense_content` 反证）→ MANUAL_REVIEW（banker01 人工复核）→ APPROVED（`payout_amount` 赔付）/ REJECTED（`reject_reason`）；
  3. 全程给租客发站内信（申请收到、申辩期开始、结案通知）。
- **房东电子签约**（缺口 #16）：G-2 房东确认环节增加协议展示 + 电子签名（Canvas 手写或点击确认），签署时间/签名入库。
- **AI 预审增强**（缺口 #17）：G-3 复审增加置信度阈值（命中高风险规则 → 置信度 <0.6 → 转 MANUAL_REVIEW，不直接 PASS）；管理端可查人工复核队列（与步骤 8 联动）。

#### ② 我该做什么

- 确认索赔状态机口径与演示话术（"损坏是否在交接清单已存在"的比对规则）；
- 确认电子签约演示方式（手写签名 canvas）。

#### ③ 产出物

- guarantee 模块扩展：Claim 四件套（Entity+Mapper+Service+Controller）+ 签约字段 + AI 复审增强；接口清单 + curl 示例 + 与 G-6/签约/预审对应表。

#### ④ 检查要点

- 索赔 7 态流转闭环、申辩期可进可出；AI 初审"低风险速赔、存疑转人工"两类路径都能演示；签约时间/签名入库；越权（非本单房东/租客）返回 4001。

### 步骤2：政策与消息层（安居政策匹配 + 贴息政策推送 + 消息中心串联 + 预算三级提醒触达）

#### ① AI 该做什么

- **人才安居政策智能匹配**（缺口 #3）：新增 `biz_policy` 政策库（人才公寓、落户补贴、就业扶持等），按用户人群资质（在校生/应届/城市青年）与画像匹配，给出"可申报入口 + 条件速览"（非新闻资讯）。
- **创业贴息政策智能推送**（缺口 #4）：政策库含创业担保贷款（个人最高 30 万、部分地区 50 万、贴息）、个体工商户税费优惠；按经营画像 + 人群资质匹配推送，可一键申报演示。
- **消息中心业务串联**（缺口 #8）：申请提交/房东确认/AI 复审/缴费出函/索赔通知/预算提醒/政策推送 **全部自动写入 `sys_message`**，用户端消息页可查未读。
- **预算三级提醒触达**（缺口 #5）：C-3 三级提醒（剩余 50%→20%→超支+结转）从"页面提示"升级为"站内信 + 风险预警双通道"（超支同步落 `biz_risk_warning` warning_type=BUDGET_OVER）。

#### ② 我该做什么

- 确认政策库演示条目（6–8 条真实政策 + "模拟"标注）与人群匹配规则；
- 确认消息文案模板口径。

#### ③ 产出物

- `biz_policy` 表 + 政策匹配/推送接口 + message 串联改造 + 预算提醒触达；接口清单 + 演示数据 + 对应表。

#### ④ 检查要点

- 政策匹配按人群资质正确命中；三场景任一动作后消息中心有对应记录；预算 50%/20%/超支三档都能触发提醒；未读数量正确。

### 步骤3：贷款增强（A 类循环贷随借随还 + B 转 A 观察期 + 商户白名单管理）

#### ① AI 该做什么

- **A 类循环贷随借随还**（缺口 #10）：对接 `biz_credit_limit`，A 类 5 万循环额度：分次提款、按实际用款天数和利率计息、归还后额度自动恢复；生成提款/还款流水（可复用 `biz_entrust_payment` 或扩展）。
- **B 转 A 观察期状态机**（缺口 #11）：B 类预审通过后进入 6 个月观察期（演示提供"加速观察"：模拟月份推进），观察期内受托支付记录 + 收款码收入 + 记账数据回流评分，达标自动转 A 类并提额；数据不足则维持小额或退出。
- **商户白名单管理**（缺口 #6）：商户列表增加"白名单/灰名单"状态，banker01 可审核；受托支付仅允许白名单商户（`biz_merchant.verify_status` 驱动）。

#### ② 我该做什么

- 确认 A 类利率口径（演示用年化 3.85% 标注"模拟"）、观察期加速方式；
- 确认白名单审核入口（用户端申请 + 管理端审核）。

#### ③ 产出物

- loan 模块扩展（循环贷/观察期/白名单）+ 接口清单 + curl 示例 + 状态机说明图（文字版）。

#### ④ 检查要点

- 提款→计息→还款→额度恢复闭环；B 转 A 达标/不达标两条路径可演示；非白名单商户受托支付被拒且提示明确。

### 步骤4：经营赋能（现金流风险预警 + 保险代销匹配 + 财税科普/个转企引导）

#### ① AI 该做什么

- **现金流风险预警**（缺口 #12）：基于记账/收支数据规则判断"账面盈利但现金紧张"（应收未收、支出前置、结余率低），命中落 `biz_risk_warning` warning_type=CASHFLOW_WARNING，并给出备货/淡旺季建议文案。
- **保险代销匹配**（缺口 #24→新增 `biz_insurance_product`）：履约保证保险、知识产权保险（专利执行/侵权责任）按经营场景推荐；页面展示产品要素 + "跳转投保"演示（模拟，标注"工行仅代销、不承保"）。
- **财税科普与个转企引导**（缺口 #25→简化）：轻量化财税科普内容（个体工商户税务优惠、发票常识）+ "个转企"条件自查与引导流程。

#### ② 我该做什么

- 确认现金流预警的模拟规则阈值（如"近 3 月结余率 <10% 且存在 >7 天应收未收"）；
- 确认保险产品演示条目与合规文案。

#### ③ 产出物

- 现金流预警规则 + 保险库/匹配接口 + 财税科普内容页 + 接口清单。

#### ④ 检查要点

- 预警触发条件可复现（造数验证）；保险推荐按经营场景命中；科普内容无违规承诺；所有金融产品标注"模拟"。

### 步骤5：消费治理（高频借贷预警 + 常态化征信监测 + 三层消费引导 + 理财匹配与风险测评）

#### ① AI 该做什么

- **高频借贷/非理性负债预警**（缺口 #13）：识别多平台借贷、短周期多次借款、"以贷养贷"特征（演示用模拟数据），命中落 `biz_risk_warning` warning_type=HIGH_FREQ_BORROW，预警页面 + 站内信。
- **常态化征信监测**（缺口 #14）：用户授权后"软查询"模拟（`biz_credit_report` source=SIMULATED，不产生硬查询），定期检查异常借贷、逾期，异常提示转 `biz_risk_warning` warning_type=CREDIT_ABNORMAL。
- **三层渐进式消费引导**（缺口 #18→简化）：① 交易后即时推送（模拟交易触发）；② 月度账单分析（消费结构诊断 + 负债预警）；③ 支付前实时提醒（演示页，标注"仅工行自有支付场景"）。
- **理财匹配与风险测评**（缺口 #7→新增 `biz_finance_product` + `biz_risk_assessment`）：风险测评问卷（≤10 题）→ 风险等级 → 仅推荐低风险产品（心愿储蓄/现金管理/短债/基金定投/积存金），首次购买强制测评，页面充分风险提示（理财非存款）。

#### ② 我该做什么

- 确认高频借贷/负债预警的模拟特征口径；
- 确认风险测评题量与结果映射（保守型/稳健型/平衡型→低风险产品池）。

#### ③ 产出物

- 消费治理扩展（预警/监测/引导/理财）+ 4 张表（如适用）+ 接口清单 + 对应表。

#### ④ 检查要点

- 三类预警（借贷/征信/预算）在风险预警页聚合可看；测评未完成不能进理财推荐；推荐产品全为低风险；无自动扣款逻辑。

### 步骤6：金融安全（征信报告智能解读 + 逾期风险预判 + 征信健康管理 + 反诈情景化教学）

#### ① AI 该做什么

- **征信报告智能解读**（缺口 #2）：用户上传/选择模拟征信报告（`biz_credit_report`）→ 结构化解读：信用分/等级、逾期笔数与原因、查询次数、负债率，逐项生成"好/差"评价与改进建议。
- **逾期风险预判**（缺口 #15）：基于还款日历（贷款/受托支付/保函费）+ 收支数据规则评分（如"还款日前余额不足 + 近期支出超预算"），命中落 `biz_risk_warning` warning_type=OVERDUE_RISK，提前 N 天预警。
- **征信健康管理**（缺口 #26→简化）：征信健康分（复用 credit_score）+ 改善清单（还清逾期、减少查询、规范还款），可"一键模拟修复路径"演示（标注不产生真实征信影响）。
- **反诈情景化教学**（缺口 #1）：基于 `biz_anti_fraud_content` 扩展"情景模拟"类型：互动问答式拆解（刷单诈骗/冒充公检法/征信洗白），选择→反馈→解析，可配积分/进度。

#### ② 我该做什么

- 确认征信解读演示报告样例（2 份：良好/有瑕疵）与预判规则；
- 确认情景教学交互形式（选择题式即可）。

#### ③ 产出物

- safety 模块扩展（解读/预判/健康/教学）+ 接口清单 + 演示报告数据。

#### ④ 检查要点

- 解读与报告数据一致（不编造指标）；逾期预判触发可复现；情景教学闭环（选错有纠偏文案）；所有征信内容标注"模拟"。

### 步骤7：智能中台（双模式对话引擎 + 多渠道流水聚合 + 防刷单三道防线 + 青年成长信用画像）

#### ① AI 该做什么

- **轻量化对话引擎 · 双模式**（缺口 #18→演示级）：金融问答 + 合同要点解析 + 诈骗情景对话，**本地规则引擎保底 + 可选 Agent AI（LLM）增强**：
  1. 后端新增 `/api/v1/chat` 适配层（鉴权 JWT），配置开关 `chat.engine=local|agent`（application.yml）；
  2. `local` 模式（默认，离线可用）：FAQ 50 条 + `biz_policy` 政策库 + `biz_anti_fraud_content` 反诈库关键词/规则召回 → 模板化回答 + **来源引用（可点开溯源）**；
  3. `agent` 模式（可选，需 API Key，endpoint 可配置，支持豆包/DeepSeek）：**本地 RAG 先召回知识片段拼入上下文**，LLM 仅负责组织语言，回答仍附本地召回来源；系统提示词固定"工行智能客服，仅基于给定上下文回答，禁止编造利率/额度/政策数字，不承诺收益"；
  4. 降级：LLM 超时/报错/断网 → 自动回退 `local` 模式；所有回答标注"模拟对话引擎/仅供参考"；
  5. **API Key 安全**：Key **不写入代码、不提交 git、不告知 AI**——代码仅读 `${CHAT_LLM_API_KEY:}` 环境变量（docker-compose 后端服务透传 `CHAT_LLM_API_KEY: ${CHAT_LLM_API_KEY:-}`），项目根 `.env` 加入 `.gitignore`，Key 由你本人在 `.env` 自行填写；Key 为空时 agent 模式自动禁用并回退 local，页面提示"AI 增强未开启"。
- **多渠道流水聚合**（缺口 #19→模拟）：用户授权演示页（勾选平台：工行收款码/微信/支付宝/淘宝店）→ 生成聚合经营流水（来源标注"已授权聚合"），支持解绑/删除（演示合规）。
