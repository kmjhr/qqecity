## 1. 适配原则确认

本报告为第二期适配工作记录，承接第一期"代码骨架 ↔ 需求文档"的对齐成果，继续向下推进数据库落地、原型设计、部署脚本和文档体系完善四大任务。

**核心适配规则（延续第一期）：**

1. **需求基准不变** — 原始设计文档中的业务功能、业务规则、用户角色、核心流程一律不修改
2. **代码优先适配** — 代码骨架与需求不符时，优先修改代码适配需求，不反向修改需求
3. **文档结构可调** — 文档仅可调整目录层级、文件命名、章节结构、排版格式，不可改动需求内容
4. **一一对应原则** — docs 目录与代码目录一一对应，新增模块必须同步补充文档

**第二期新增适配原则：**

5. **数据库必须对齐需求第 6 章** — 表数量、表名、字段、主外键关系必须与说明书第 6 章一致
6. **原型必须对齐需求第 5 章** — 页面清单、字段、流程必须与模块职责对应
7. **部署文档必须可操作** — 每一条部署步骤必须可在新机器上从零复现
8. **脚本必须幂等** — 数据库初始化、数据导入等脚本可重复运行不报错

### 3.2 数据库设计关键决策

| 决策点 | 方案 | 对应需求 |
|--------|------|----------|
| 用户类型 | userType 字段（STUDENT/GRADUATE/ENTREPRENEUR/OTHER） | 需求 P-1.1 注册人群分类 |
| 角色体系 | 独立 sys_role + sys_user_role 关联表，支持多角色 | 需求第 2 章角色定义（5 类角色） |
| 消息关联 | bizType + bizId 通用关联字段，支持各模块消息 | 需求 P-4 消息中心多来源 |
| 金额字段 | 全部 DECIMAL(15,2)，不使用 FLOAT/DOUBLE | 金融系统精度要求 |
| 逻辑删除 | deleted 字段（0 存在 / 1 删除），MyBatis-Plus 原生支持 | 数据安全与可追溯 |
| 时间字段 | create_time / update_time 自动填充 | 通用审计需求 |
| 字符集 | utf8mb4（支持 emoji 及所有 Unicode 字符） | 昵称、消息内容等可能含特殊字符 |
| 状态枚举 | 全部使用 VARCHAR + 字符串状态值，可读性好 | 开发与调试友好 |

## 5. 部署脚本与文档适配清单

### 5.1 部署脚本集（20 个）

**目录结构：**
```
scripts/
├── README.md                    # 脚本使用说明
├── windows/                     # Windows 平台（10 个 .bat）
│   ├── config.bat               # 统一配置
│   ├── 00-check-env.bat         # 环境检查
│   ├── 01-init-db.bat           # 数据库初始化
│   ├── 02-verify-db.bat         # 数据库验证
│   ├── 03-verify-redis.bat      # Redis 验证
│   ├── 04-init-project.bat      # 项目初始化
│   ├── 05-start-backend.bat     # 启动后端
│   ├── 06-start-user-web.bat    # 启动用户前端
│   ├── 07-start-admin-web.bat   # 启动管理前端
│   └── 99-start-all.bat         # 一键全部启动
└── linux/                       # Linux 平台（10 个 .sh）
    ├── config.sh                # 统一配置
    ├── 00-check-env.sh
    ├── 01-init-db.sh
    ├── 02-verify-db.sh
    ├── 03-verify-redis.sh
    ├── 04-init-project.sh
    ├── 05-start-backend.sh
    ├── 06-start-user-web.sh
    ├── 07-start-admin-web.sh
    └── 99-start-all.sh
```

**脚本设计原则：**

| 原则 | 实现方式 |
|------|----------|
| 双平台功能一致 | Windows 和 Linux 脚本编号对应，功能完全对齐 |
| 统一配置入口 | 所有脚本共用 config.bat/config.sh，修改一处全局生效 |
| 幂等可重复 | 数据库初始化使用 CREATE TABLE IF NOT EXISTS + INSERT IGNORE |
| 自动检测依赖 | 启动时检测 jar 包 / node_modules，不存在则自动编译/安装 |
| 渐进式验证 | 从环境检查到数据库验证到 Redis 验证，每一步都有确认 |
| 一键启动 | 99-start-all 脚本串联全部启动流程 |
