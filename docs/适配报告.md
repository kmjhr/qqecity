# 青启e城 · 代码骨架与文档适配报告

> 适配基准：以原始设计文档（需求清单、设计说明书）业务内容为唯一真值，代码骨架向文档对齐，文档仅做结构/命名/格式调整。

---

## 1. 适配原则确认

本次适配严格遵循以下核心规则：

1. **需求不可变**：原始设计文档中的业务功能、业务规则、用户角色、核心流程一律不修改；
2. **代码迁就文档**：代码骨架与需求不符时，优先修改代码骨架适配文档，不能反过来改需求；
3. **文档仅结构调整**：文档仅可调整目录层级、文件命名、章节结构、排版格式，不可改动需求内容；
4. **目录一一对应**：docs 目录必须和代码目录一一对应，代码有什么模块，docs 就有对应的子目录和文档；
5. **所有修改明确标注**：区分「代码骨架修改」和「文档结构修改」两类，每条修改都有明确记录。

**确认**：本次适配以 `docs/common/requirements.md`（原《需求清单》）为业务需求基准。
