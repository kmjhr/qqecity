## 1. 背景与定位

当前各模块的资金动作是 "各管各的"：保函缴费直接置 `pay_status=PAID`、受托支付直接置 `payment_status=SUCCESS`、还款只扣额度不经过任何账户 —— 没有统一的订单、余额、流水与收银台，演示 "像银行" 但 "不像支付"。

本设计新增**模拟支付中台**：每个用户一个模拟电子钱包 + 每个商户一个模拟收款账户，所有资金动作走「**下单 → 收银台支付 → 入账 / 出账 → 流水**」闭环，覆盖：



| 场景              | 现状                    | 改造后                                                  |
| --------------- | --------------------- | ---------------------------------------------------- |
| 保函缴费（G-4）       | 直接置 PAID              | 生成订单 → 收银台 → 钱包扣款 → 置 PAID + 流水                      |
| A 类提款           | 额度转已用                 | 放款入钱包（额度 → 钱包），流水可查                                  |
| A/B 还款          | 只扣额度                  | 钱包扣款（余额不足提示充值）→ 还本付息                                 |
| B 类受托支付（L-3）    | 直接置 SUCCESS           | 订单 → 银行资金 → 商户账户入账（仍不经过个人钱包）                         |
| 模拟消费（淘宝式，模块 3）  | 直接生成 biz\_transaction | 商户商城下单 → 收银台 → 钱包支付 → 商户入账 + 同步写 biz\_transaction 归类 |
| 商户收款 / 余额       | 无                     | 商户账户余额入账、账单可查                                        |
| 退款（保函失效 / 消费退款） | 无                     | 订单退款 → 钱包退回 + 流水                                     |

**模拟声明**：不接真实支付通道、不产生真实资金；全部标注 "模拟"。充值 / 支付 / 放款均为桩逻辑。

## 2. 账户与资金流模型



```
&#x20;                   ┌─────────────────────────────┐

&#x20;                   │       模拟资金池（银行侧）      │

&#x20;                   │  放款 / 受托支付 / 充值来源     │

&#x20;                   └──────────────┬──────────────┘

&#x20;                                  │ 放款（A类提款）／受托支付直付商户

&#x20;             ┌────────────────────┼─────────────────────┐

&#x20;             ▼                    ▼                     ▼

&#x20;   ┌─────────────┐        ┌──────────────┐      ┌──────────────┐

&#x20;   │  用户钱包    │◄───────│ 保函费/还款/消费│      │  商户账户     │

&#x20;   │ pay\_wallet  │        │ 扣款          │      │ pay\_merchant │

&#x20;   │  余额/冻结   │        └──────────────┘      │   余额/账单   │

&#x20;   └──────┬──────┘                               └──────┬───────┘

&#x20;          │ 充值（模拟银行卡/工行e支付）                    ▲

&#x20;          ▼                                              │ 受托支付/消费收款

&#x20;   ┌─────────────┐                              ┌────────┴───────┐

&#x20;   │ 模拟银行卡    │                              │  订单+流水      │

&#x20;   │（桩数据）     │                              │ pay\_order      │

&#x20;   └─────────────┘                              │ pay\_transaction│

&#x20;                                                └────────────────┘
```

**关键规则**



1. 用户钱包是唯一个人资金入口：提款入钱包、还款 / 缴费 / 消费从钱包出。

2. B 类受托支付**不经过个人钱包**：银行资金 → 商户账户（与现有 "资金不经过个人账户" 一致，但补订单与商户入账记录）。

3. 商户账户：每家在 `biz_merchant` 下的模拟收款账户，入账来源 = 受托支付 + 模拟消费。

4. 所有出入均写 `pay_transaction`，业务侧保留各自状态位（`pay_status` / `payment_status`）作为对账冗余。

```
CREATE TABLE \`pay\_transaction\` (

&#x20; \`remark\`       VARCHAR(500)  NULL COMMENT '备注',

&#x20; \`create\_time\`  DATETIME      NOT NULL DEFAULT CURRENT\_TIMESTAMP COMMENT '创建时间',

&#x20; UNIQUE KEY \`uk\_txn\_no\` (\`txn\_no\`),

&#x20; KEY \`idx\_user\_id\` (\`user\_id\`),

&#x20; KEY \`idx\_merchant\_id\` (\`merchant\_id\`),

&#x20; KEY \`idx\_order\_no\` (\`order\_no\`),

&#x20; KEY \`idx\_create\_time\` (\`create\_time\`)

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='支付流水表（模拟）';
```

> 退款在 
>
> `pay_order.status=REFUNDED`
>
>  表达（退款金额 = 订单金额，演示从简，不设独立退款表；若后续要部分退款再拆 
>
> `pay_refund`
>
> ）。

**新增理由**：25 张表现有表均为 "业务结果记录"（保函 / 受托支付 / 交易归类），无账户余额、无订单状态机、无统一流水；支付中台三要素（账户 / 订单 / 流水）均缺失，必须新增。`biz_guarantee.pay_status`、`biz_entrust_payment.payment_status` 保留，作为业务侧状态与支付侧对账。

## 5. 页面与交互流程（user-web 新增 2 页 + 收银台弹窗）



| 页面      | 路由                  | 内容                                                                                   |
| ------- | ------------------- | ------------------------------------------------------------------------------------ |
| 我的钱包    | `/wallet`           | 余额大字卡、充值按钮（模拟）、近 20 笔流水（收支 / 类型图标）、支付密码设置入口                                          |
| 收银台（弹窗） | 组件 `PayCashier.vue` | 订单标题 / 金额 / 商户 / 超时倒计时、支付方式单选（钱包余额 / 模拟银行卡 / 工行 e 支付）、支付密码输入（模拟 6 位）、"模拟支付" 按钮、风控提示条 |

**关键交互（淘宝感）**



1. 各业务点（保函详情缴费、还款中心、预算页模拟消费）→ 生成订单 → 弹收银台；

2. 收银台默认选中 "钱包余额"，余额不足时红色提示 + "去充值" 按钮；

3. 支付成功：对勾动画 + "已支付" + 订单流水可查；失败：明确原因（余额不足 / 密码错误 / 风控拦截）；

4. 订单 15 分钟未支付自动关闭（演示提供手动关闭）。

## 6. 状态机



```
订单: PENDING\_PAY ──pay──▶ PAID ──refund──▶ REFUNDED

&#x20;       │                   │

&#x20;       └──close/超时──▶ CLOSED

支付（钱包）: 校验密码 → 校验余额 → 冻结金额 → 扣款 → 解冻 → 写流水(SUCCESS)

&#x20;             │余额不足/密码错│

&#x20;             └──▶ FAILED（流水留痕，订单仍待支付）

受托支付: 创建订单(ENTRUST\_PAY) → 模拟银行放款 → 商户账户 balance+ / total\_income+ → 订单 PAID
```

## 7. 模拟标注、风控与安全



1. **全程标注 "模拟"**：收银台、充值、流水、页面顶部均标注（与全项目口径一致）。

2. **支付密码**：模拟 6 位数字，默认 `123456`，首次支付强制设置；错误 3 次锁定（模拟，需管理端解锁）。

3. **余额不足**：返回 `3001` + "余额不足，请先充值（模拟）"。

4. **防重 / 一致性**：订单号唯一 + 钱包行级乐观锁（`update balance=balance-? where balance>=?`），支付幂等（重复支付返回已支付）。

5. **反诈联动**（加分项）：消费下单 / 支付前走 `biz_fraud_detection_log` 风控词校验，命中高危词（垫资 / 保证金 / 解冻）拦截并提示（对应补充计划书 #18 支付前提醒）。

6. **数据隔离**：钱包 / 订单 / 流水全部按 `user_id` 隔离，越权访问返回 `4001`。
