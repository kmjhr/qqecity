# 模块2：轻创业智能授信模块 设计书

> 版本：v1.0（2026-09-28）
> 依据：《工行杯9.26.docx》P107-108 模块2 定义 + P63-84 场景二详细设计 + P119 画像建模 + P123 四重风控
> 范围：青创e贷 A/B 双轨授信全链路（流水聚合 → 画像 → 授信 → 提款/受托支付 → 观察期晋级 → 政策推送）
> 技术栈：Java17 + Spring Boot3.2 + MyBatis-Plus + MySQL8 + Redis + JWT；银行能力全部模拟并标注"模拟"

---

## 1. 定位与目标

面向城市市集、文创创作、校园服务、本地生活服务等青年轻创业新业态，提供专属个人经营性贷款产品「青创e贷」，构建 **A/B 双轨、边经营边画像** 的小微授信体系。

**边界声明（对齐文档 P64）**：青创e贷是**个人经营性贷款**，资金仅限合法经营用途；不是信用卡，不允许信用卡资金流入经营领域；演示产品复用工行"经营快贷/融e借"能力（全部模拟）。

**六大能力（文档 P108）**：① 多渠道经营流水聚合分析 ② 青年创业信用画像建模 ③ A/B 双轨授信 ④ 随借随还循环贷款 ⑤ B类两步式审批与受托支付 ⑥ 创业贴息政策智能推送。

## 2. 现状对照（本次代码核查结论）

对照文档设计与当前 `backend` 实现（2026-09-28 核查）：

| # | 文档要求 | 当前实现 | 状态 |
|---|---|---|---|
| 1 | 多渠道流水聚合：工行收款码+卡收支+授权聚合第三方，来源标注"已授权聚合"、可解绑 | `cashflow` 模块：`GET/POST/DELETE /api/v1/cashflow/aggregate/auth`（授权/查询/**解绑**）+ `/report` 聚合报表 + `AntiBrush` 防刷单 | ✅ 完整 |
| 2 | 青年创业信用画像：经营稳定性/收入连续性/客单与复购/履约记录 | `profile` 模块：三维画像（安居稳定性/创业经营力/消费资金健康度，30/40/30 加权）+ `applyLinkage` 联动提额（安居稳+经营好→A类提额+利率优惠，真实写 `biz_credit_limit`） | ✅ 主体，⚠️ 经营力未细分四个子维度独立指标 |
| 3 | A/B 双轨授信 | A类 `biz_credit_limit(A_TYPE)` 自动创建+`myCreditLimits`；B类 `precheck` 预审+贷款申请+admin 审核 | ✅ |
| 4 | 随借随还循环贷：分次提款/按实际使用金额与天数计息/归还后额度恢复 | `withdraw`（校验可用额度→扣减→写 `biz_credit_txn`）；`repay`（找最早未还提款按**计息天数**算息→还本→**恢复额度**） | ✅ |
| 5 | B类两步式审批：①免费预审（人群资质+创业计划→额度区间，**不查征信不收费**）②正式提款（确认真实交易+指定收款商户，**100%受托支付**直付商户账户） | `precheck`（`SUPPORTED_CROWDS` 人群白名单 + `PLAN_KEYWORDS` 计划关键词 → 额度区间，PASS/FAIL，免费）；`entrustPay`（校验申请状态 APPROVED + 商户启用 + **VERIFIED 白名单**，资金直付商户） | ✅ |
| 6 | 创业贴息政策智能推送：画像精准匹配→推送可申报入口（非新闻） | `policy` 模块：`PolicyService` 人群标签匹配 + `sendInternalMessage` 写 `sys_message(POLICY)` 站内信推送 | ✅ |
| 7 | B类兜底一：有额度未发生交易→额度有效期后自动失效 | `biz_credit_limit.expireDate` 字段存在，但**无运行时"到期→CLOSED"判定**（`getActiveACreditLimit` 仅查 status） | ⚠️ 字段有、逻辑缺失 |
| 8 | B类兜底二：提款后经营失败→保险/担保代偿、展期续贷 | 未见代偿/展期接口 | ❌ 未实现（模拟可后置） |
| 9 | B转A：6个月观察期，受托支付/收款码/记账回流→稳定达标转A提额、数据不足退出 | `advanceObservation`：`observationStatus = OBSERVING/PROMOTED/EXITED` 状态机 + `getObservationStatus` | ✅ 逻辑在，⚠️ 达标/退出两路径未造数验证 |
| 10 | 四重风控：人群白名单/小额上限/专款专用/交易实时监控 + AI初审人工复核 | `SUPPORTED_CROWDS` + `LIMIT_MAX(2万)` + 受托支付专款专用 + `CashflowWarning`(现金流预警)/`AntiBrush`(防刷单)；admin `LoanReview` AI 初审+人工复核 | ✅ |

**结论**：六大能力全部有对应实现，无"整块缺失"；差异集中在 3 处增强点（见 §5）。

## 5. 差异/缺失项清单与补齐建议

### 5.1 已闭环（无需改动）
流水聚合+解绑、A/B双轨、随借随还、两步式审批+受托支付白名单、政策推送、四重风控、联动提额。

### 5.2 增强点 A：画像经营力子维度细化（建议做，演示加分）
**现状**：`scoreOperation` 以聚合流水规模/受托支付笔数/记账活跃度打综合分，未独立呈现"收入连续性/客单与复购/履约记录"。
**建议**（复用 `biz_cashflow_report` + `biz_entrust_payment` + `biz_bookkeeping_record`，零新增表）：
- 收入连续性：近 6 月有收入月份占比 + 月收入标准差 → 连续/波动/中断
- 客单与复购：月均单笔金额 + 重复商户/品类占比
- 履约记录：受托支付按时完成率 + 保函履约（联动稳定性）
- 输出：画像页新增"经营力明细"四子项打分，供 A 类初始授信档位与联动提额引用

### 5.3 增强点 B：B类预审额度到期自动失效（建议做，对应文档 P76）
**现状**：`biz_credit_limit.expireDate` 有字段，无运行时判定。
**建议**：`myCreditLimits`/`withdraw` 前统一校验 `expireDate < today → status=CLOSED`，返回"预审额度已到期自动失效（不产生负债）"。

### 5.4 后置项 C：B类提款失败兜底（文档 P77，模拟系统建议后置）
保险/担保代偿、展期续贷、逾期催收流程 —— 涉及保险代销与担保能力，超出当前演示闭环，标注"模拟延后"，不新增表。

### 5.5 测试缺口 D：B转A 达标/退出路径
`advanceObservation` 已实现 NONE→OBSERVING 与 PROMOTED/EXITED 状态机，但此前仅验证"非观察期拒绝"；需造数验证两条路径：达标（受托支付≥2笔+收款码收入达阈值+履约良好→PROMOTED 提额）与数据不足退出（EXITED 维持小额/退出）。

## 7. 演示脚本（工行杯路演口径）

1. **流水聚合**：用户授权聚合第三方经营流水 → 报表显示工行收款码+微信+支付宝合并经营视图，来源标注"已授权聚合"，可解绑
2. **B类两步式**：新创业者提交创业计划+人群资质 → 免费预审通过、给额度区间（不查征信提示）→ 指定白名单收款商户（物料采购）→ 100%受托支付直付商户
3. **B转A**：观察期数据回流（受托支付+收款码+记账）→ 达标晋级 A 类纯信用循环额度并提额、利率优惠
4. **A类随借随还**：按市集周期分次提款 → 资金回笼随时还 → 按实际天数计息 → 额度自动恢复
5. **政策推送**：画像匹配创业担保贷款+贴息政策 → 消息中心收到"可申报入口"推送 → 一键跳转政策匹配页
6. **四重风控展示**：白名单（非在校生/毕业>2年拒绝）、小额上限（≤2万）、专款专用（受托支付）、实时监控（现金流预警+防刷单），管理端 AI 初审+人工复核留痕

## 8. 约束与合规（对齐文档 P74/P136-139）

- 受托支付：B 类**主动全额**采用（文档口径较《个人贷款管理办法》50 万强制线更审慎）
- 征信合规：预审阶段不查询征信、不产生硬查询；监测采用软查询
- 数据合规：聚合流水须用户逐项授权、可解绑删除；传输加密、脱敏建模、操作留痕
- 模拟标注：放款/受托支付/晋级全部"模拟"，无真实资金
